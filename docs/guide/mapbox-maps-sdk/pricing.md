# Mapbox 지도 SDK의 요금 산정

> **면접 답변 한 줄 요약:** Maps SDK의 기본 과금 단위는 지도 기능을 이용한 월간 활성 사용자이며, 지도 화면 호출 횟수와 같은 값으로 보면 안 돼요.

공식 [Pricing](https://docs.mapbox.com/ios/maps/guides/pricing/)에 대응해요. 계약에 대한 해석이나 요금 견적이 아니라, 개발자가 사용량을 이해하기 위한 안내예요. 금액은 고정해 적지 않고 출시 시점의 가격표와 계약을 확인해요.

## 먼저 알아둘 용어

| 용어                     | 쉬운 뜻                                                              |
| ------------------------ | -------------------------------------------------------------------- |
| MAU(Monthly Active User) | 한 청구 주기 동안 기능을 사용한 사용자 수를 나타내는 과금 지표예요.  |
| 청구 주기                | 사용량을 합산하는 계정별 기간이에요.                                 |
| 무료 구간                | 가격 정책이 정한 사용량 범위예요. 영구적인 약속으로 가정하지 않아요. |

## 앱 로그인 수와 지도 MAU를 구분해요

공식 문서는 Maps SDKs for Mobile MAU를 기준으로 설명해요. 지도 표시 등 SDK 기능을 사용하면 활성으로 집계될 수 있어요. 기간은 계정의 청구 주기이므로 달력상의 매월 1일과 같다고 단정하지 않아요.

앱을 삭제하지 않은 업그레이드는 사용자 식별을 유지하지만, 삭제 후 재설치는 추가 MAU가 될 수 있어요. 따라서 앱의 로그인 분석 지표와 Mapbox 사용량을 억지로 일치시키지 않는 편이 좋아요.

## 포함 범위는 서비스별로 확인해요

원문은 별도 연간 계약 등이 없는 Maps SDK 앱에서 사용하는 Vector Tiles API와 Raster Tiles API를 MAU 범위와 연결해 설명해요. 이를 모든 Mapbox 제품이 무료라는 의미로 확장하지 않아요.

예를 들어 앱이 지도, 장소 검색, 경로 기능을 함께 사용한다면 다음과 같이 제품 사용을 나눠 기록해 보세요.

| 앱 동작            | 확인할 항목                            |
| ------------------ | -------------------------------------- |
| 지도 화면 탐색     | Maps SDK의 활성 사용자 기준            |
| 검색 결과 표시     | 실제 호출하는 검색 제품과 그 요금 정책 |
| 길 안내 시작       | 사용하는 내비게이션 제품과 계약        |
| 오프라인 영역 저장 | 다운로드 제약과 관련 제품 조건         |

이 표는 공식 비용 계산식이 아니라, 누락된 제품 사용을 찾는 점검표예요.

## 숫자를 하드코딩하기 전에 가정을 적어요

학습용 예산 검토에서는 금액 대신 다음 가정을 먼저 적는 편이 좋아요.

```text
청구 기간: 계정 화면에서 확인
지도 사용 사용자: 앱 전체 사용자 중 지도 기능을 쓴 범위
재설치·테스트 사용: 별도 변동 요인으로 기록
사용 제품: Maps / Search / Navigation 등 구분
요금표 확인일·계약: 검토 기록에 함께 저장
```

이후 실제 계정의 사용량과 비교하고 차이를 설명해요. 개발용 지표만으로 청구서를 완전히 재현할 수 있다고 가정하지 않아요. 비용 절감을 위해 동의·attribution 기능을 제거하는 방식도 선택하지 않아요.

## 적용 체크리스트

- [ ] 청구 기간과 달력상의 월을 구분했나요?
- [ ] 화면 조회 수를 MAU로 오해하지 않나요?
- [ ] 함께 사용하는 다른 제품을 확인했나요?
- [ ] 무료 구간·단가·계약을 최신 기준으로 검토했나요?

## 면접에서 이어질 수 있는 질문

### 지도를 열 번 보면 열 MAU인가요

화면 횟수를 그대로 더하는 모델이 아니에요. 공식 활성 사용자 식별 기준을 따라요.

### 앱 사용자 분석과 수치가 다른 이유는 무엇인가요

활성 판단, 청구 기간과 재설치 처리 기준이 다를 수 있어요. 먼저 집계 정의를 맞춰 비교하세요.

### 무료 구간을 코드에 상수로 넣어도 되나요

요금 정책은 바뀔 수 있어요. 제품 요구라면 확인일과 갱신 책임을 정하고 계약과 함께 관리하세요.
