# Swift로 이해하는 Mapbox 사용자 상호작용

> **면접 답변 한 줄 요약:** 지도 상호작용은 지도를 움직이는 조작과 지도 속 대상을 선택하는 조작을 나누고, 각 이벤트가 어떤 화면 동작을 수행할지 연결하는 기능이에요.

공식 [User Interaction](https://docs.mapbox.com/ios/maps/guides/user-interaction/)에 대응하는 학습 진입점이에요. 지도 이동 설정, 특정 대상의 탭·길게 누르기, 콘텐츠가 겹친 곳의 이벤트 처리를 각각 별도 문서로 읽을 수 있어요.

## 먼저 알아둘 용어

| 용어        | 쉬운 뜻                                                             |
| ----------- | ------------------------------------------------------------------- |
| 제스처      | 누르기·끌기·확대처럼 손가락으로 입력하는 동작이에요.                |
| Feature     | 지도에 표시되는 장소·건물·경로 같은 지리 객체예요.                  |
| Featureset  | 상호작용할 수 있도록 스타일에서 묶어 제공하는 지리 객체 집합이에요. |
| 이벤트 전파 | 위쪽 대상이 처리하지 않은 입력이 다른 대상으로 전달되는 과정이에요. |

## 화면 동작을 세 종류로 분류해요

| 요구 사항                 | 연결할 문서                                     | 먼저 정할 화면 정책         |
| ------------------------- | ----------------------------------------------- | --------------------------- |
| 지도를 확대하고 회전해요  | [기본 제스처](./gestures.md)                    | 회전·기울기를 허용할지      |
| 지도 속 장소를 선택해요   | [Interactions API](./interactions.md)           | 선택 대상과 선택 해제 방식  |
| 겹친 주석과 지도를 눌러요 | [지도 콘텐츠 제스처](./map-content-gestures.md) | 어느 대상에서 입력을 끝낼지 |

“지도 전체에 탭 하나만 붙이면 된다”로 시작하면 버튼·주석·기본 장소 라벨을 누른 경우를 구분하기 어려워요. 다음과 같이 앱이 이해할 동작을 먼저 적어볼 수 있어요.

```swift
enum StoreMapAction: Equatable {
    case beginBrowsing
    case selectStore(id: String)
    case clearSelection
}
```

이 타입은 SDK 콜백을 그대로 저장한 것이 아니라 앱의 학습용 입력 모델이에요. 지도 구현을 바꾸더라도 “매장을 선택하면 상세 카드를 표시한다”는 규칙을 유지할 수 있어요.

## SDK 입력과 앱 동작 사이에 작은 경계를 둬요

다음 흐름은 한 번의 입력으로 여러 화면이 동시에 열리는 문제를 찾을 때 유용해요.

```text
손가락 입력 → 지도에서 대상 판별 → 앱 동작 하나 선택 → 화면 상태 변경
                                   └─ 처리하지 않음: 다음 대상으로 전파
```

상세 화면 이동, 선택 강조, 검색 요청을 모두 지도 콜백 안에서 직접 처리하기보다 앱 동작을 한 번 만들어 전달해 보세요. 이 경계는 테스트에서 실제 지도 없이도 선택·해제 순서를 검증하게 해줘요.

## 적용 순서를 정리해요

1. 지도 이동과 대상 선택을 서로 다른 기능으로 적어요.
2. 한 입력이 실행할 앱 동작을 명확히 해요.
3. 지도 빈 곳을 누를 때의 동작을 정해요.
4. 겹친 대상과 빠른 연속 탭을 테스트해요.
5. 화면 종료 시 등록한 이벤트의 수명을 확인해요.

## 면접에서 이어질 수 있는 질문

### 카메라 제스처와 장소 선택은 같은가요?

아니요. 하나는 보는 범위를 바꾸고 다른 하나는 지리 객체를 선택해요. 각각 다른 화면 정책이 필요해요.

### 지도 콜백 안에서 화면 이동까지 해도 되나요?

작은 화면에서는 가능하지만 테스트와 재사용 범위가 좁아질 수 있어요. 앱 동작으로 바꿔 전달하면 지도 API와 화면 흐름의 결합을 줄일 수 있어요.

### 전파를 왜 명시적으로 정하나요?

한 번의 탭으로 주석 선택과 지도 빈 곳 동작이 함께 실행되지 않게 하기 위해서예요. 입력을 처리한 곳에서 끝낼지 다음 대상으로 넘길지 결정해요.
