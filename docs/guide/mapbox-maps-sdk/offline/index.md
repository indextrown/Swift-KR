# Mapbox 오프라인 지도 시작하기

> **면접 답변 한 줄 요약:** 오프라인 지도는 필요한 지역의 지도 데이터를 미리 준비해 연결이 끊겨도 보여 주는 기능이며, 다운로드뿐 아니라 범위·갱신·삭제 정책까지 함께 설계해야 해요.

여행 앱에서 “산책 지도를 저장했으니 지하철에서도 볼 수 있다”고 안내하려면 무엇을 저장했는지 설명할 수 있어야 해요. 화면을 한 번 열어 본 사실만으로 여행 전체의 지도를 보장할 수는 없어요.

이 문서는 공식 **Offline Maps** 페이지에 대응하는 시작점이에요. 저장 구조는 [개념과 제약](./concepts.md), 실제 API 연결은 [오프라인 데이터 관리](./manage-offline-data.md)에서 이어서 다뤄요.

## 먼저 알아둘 용어

| 용어          | 쉬운 뜻                                                              |
| ------------- | -------------------------------------------------------------------- |
| 오프라인 범위 | 인터넷 없이 제공하기로 정한 지역·확대 수준·지도 스타일의 조합이에요. |
| 캐시          | 다시 요청할 가능성이 있는 데이터를 잠시 남겨 두는 저장 방식이에요.   |
| 갱신          | 이전 다운로드를 필요한 최신 리소스로 보완하는 작업이에요.            |

## 다운로드 버튼보다 사용 조건을 먼저 정해요

Mapbox는 지정한 지역과 확대 수준에 필요한 데이터를 미리 내려받는 기능을 제공해요. 원문은 데이터 최신성, 기기 저장 공간, 일부 동적 기능의 제한과 누적 **고유 Tile Pack 750개** 제한을 함께 안내해요. Tile Pack은 여러 지도 조각을 모은 내부 저장 단위이며, “지역을 750개 만들 수 있다”는 뜻이 아니에요. [공식 오프라인 개요](https://docs.mapbox.com/ios/maps/guides/offline/)

다음은 산책 앱을 위한 작성자 설계 예시예요. Mapbox가 정한 제품 정책은 아니에요.

| 제품 질문                  | 예시 결정                                    | 확인할 실패 상황                                   |
| -------------------------- | -------------------------------------------- | -------------------------------------------------- |
| 어디까지 걸을 수 있나요?   | 선택한 산책로 주변만 저장해요.               | 경로를 벗어나면 안내가 필요한가요?                 |
| 무엇이 계속 보여야 하나요? | 배경 지도와 앱이 보관한 산책 경로예요.       | 실시간 혼잡도를 오프라인 데이터로 오해하지 않나요? |
| 언제 다시 받나요?          | 사용자가 여행 전에 갱신해요.                 | 오래된 데이터의 날짜를 알 수 있나요?               |
| 용량이 부족하면요?         | 새 다운로드를 멈추고 지역별 삭제를 제공해요. | 기존 여행 지도를 무단 삭제하지 않나요?             |

## 준비됨은 두 데이터의 완료를 뜻해요

[개념 문서](./concepts.md)에서 다루는 Style Pack은 지도의 표현 리소스, Tile Region은 지역에 필요한 지도 타일을 관리해요. 둘 중 하나만 준비된 상태와 전체 준비 상태를 제품 모델에서 나누세요.

아래는 SDK 구현이 아니라 화면의 상태를 설계한 작은 Swift 예제예요.

```swift
enum OfflineTripState: Equatable {
    case notPrepared
    case preparing
    case ready(updatedAt: String)
    case needsAttention(message: String)
}
```

`ready`는 다운로드 버튼을 눌렀다는 뜻이 아니에요. 실제 작업 결과를 모은 뒤에만 전환하는 상태예요. `needsAttention`에는 재시도할 수 있는 이유와 기존 지도를 사용할 수 있는지를 함께 안내하는 편이 좋아요.

## 학습 순서와 인수 테스트를 연결해요

1. [개념과 제약](./concepts.md)에서 캐시, Style Pack, Tile Region을 구분해요.
2. [데이터 관리](./manage-offline-data.md)에서 두 다운로드의 결과와 취소 핸들을 관리해요.
3. 앱을 종료한 뒤 네트워크 없이 다시 실행하는 시나리오를 시험해요.
4. 저장한 지역의 경계와 최소·최대 확대 수준을 이동해 봐요.
5. 갱신 실패와 삭제 후에도 화면의 안내가 실제 상태와 맞는지 확인해요.

다운로드가 가능한 환경에서 테스트를 끝내면 이미 받은 캐시가 누락을 가릴 수 있어요. 네트워크를 끊고 실제 사용 범위를 이동하는 검증까지 완료 기준에 넣으세요.

## 면접에서 이어질 수 있는 질문

### 한 번 본 지도와 오프라인 지도의 차이는 무엇인가요?

캐시는 다시 쓰기 위한 최적화이고, 오프라인 기능은 앱이 제공할 범위를 명시적으로 관리하는 기능이에요. 성공 여부도 화면을 한 번 그렸는지가 아니라 약속한 범위로 검사해야 해요.

### 오프라인 지도가 있으면 실시간 정보도 유지되나요?

그렇지 않아요. 앱의 실시간 서버 정보와 다운로드한 배경 지도는 별개예요. 여행 경로·검색 결과·혼잡도 각각의 오프라인 정책을 정해야 해요.

### 가장 먼저 결정할 것은 무엇인가요?

사용자가 연결 없이 해야 할 행동이에요. 그 행동이 정해져야 필요한 지역, 확대 수준과 갱신 시점을 정할 수 있어요.
