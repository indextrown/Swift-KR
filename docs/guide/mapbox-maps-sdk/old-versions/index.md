# Mapbox 이전 버전 문서 읽기

> **면접 답변 한 줄 요약:** 이전 버전 문서는 기존 앱의 구조를 해석하기 위한 자료이며, API 이름과 지원 조건을 현재 버전에 그대로 적용하면 안 돼요.

공식 [Previous versions](https://docs.mapbox.com/ios/maps/guides/old-versions/)에 대응해요. 원문은 v10 문서와 지원이 종료된 v6 자료를 구분해 안내해요. 특정 릴리스의 장기 지원을 보장하는 목록으로 해석하지 않아요.

## 먼저 알아둘 용어

| 용어          | 쉬운 뜻                                                    |
| ------------- | ---------------------------------------------------------- |
| Legacy        | 새 개발의 기본값이 아닌 과거 구현·자료를 가리켜요.         |
| Major version | 큰 API 변경을 구분하는 버전의 첫 숫자예요.                 |
| Migration     | 기존 데이터와 동작을 유지하며 새 구조로 옮기는 작업이에요. |

## 예제의 출발점을 구분해요

| 발견한 코드                                 | 먼저 볼 자료                      |
| ------------------------------------------- | --------------------------------- |
| `MGLMapView`, `import Mapbox`               | [v6 → v10](./migrate-to-v10.md)   |
| `ResourceOptionsManager`, `mapboxMap.style` | [v10 → v11](../migrate-to-v11.md) |
| `MapboxOptions`, 타입별 Signal              | 현재 v11 가이드와 실제 릴리스     |

이 표는 코드를 분류하는 실마리이지 정확한 버전 판별기는 아니에요. 호환 API가 남아 있을 수 있으니 `Package.resolved`와 설치 기록으로 확인하세요.

## 기존 사용자를 먼저 생각해요

앱을 새로 설치하는 시나리오만 테스트하면 저장된 지도와 권한 상태를 놓치기 쉬워요. 학습용 검증은 “이전 앱 설치 → 데이터 저장 → 앱 업데이트 → 지도 재진입” 순서로 만들어 보세요.

옛 문서의 최소 OS·Xcode 버전은 당시 조건이에요. 최신 릴리스의 요구 사항으로 대체해서 읽지도, 과거 숫자를 새 설치에 그대로 사용하지도 않아요.

## 적용 체크리스트

- [ ] 실제 설치 버전을 먼저 확인했나요?
- [ ] API 레퍼런스의 버전 선택이 맞나요?
- [ ] 업데이트 설치와 새 설치를 나눠 시험하나요?
- [ ] 과거 예제와 현재 API를 한 코드 블록에서 섞지 않나요?

## 면접에서 이어질 수 있는 질문

### 예제에서 MGL 접두어가 보이면 무엇을 확인하나요

문서의 SDK 세대와 설치 버전을 확인해요. 새 v11 코드에 그대로 붙이지 않아요.

### v10 단계를 반드시 제품으로 출시해야 하나요

중간 버전을 출시해야 한다는 뜻은 아니에요. 구조 변화의 두 단계를 각각 이해하고 검증하라는 학습 순서예요.

### 이전 버전 문서는 왜 남겨 두나요

기존 구현과 저장 데이터의 의미를 추적할 때 필요해요. 새 기능 권장 자료와 목적이 달라요.
